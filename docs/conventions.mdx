# Conventions

Component pages document their supported props. The [API and migration policy](https://github.com/ls1intum/tum-aet-ui-react/blob/main/docs/migration-policy.md) defines state conventions and compatibility requirements.

- **Element props and refs.** `Input` and `Textarea` forward native props and refs directly. `Checkbox`, `RadioButton` and `ToggleSwitch` refs target their real native inputs. Their `className` and `style` target the visual wrapper (for sizing, layout and descendant styling); all other native props and events target the input. `RadioGroup` props/ref target its fieldset.
- **`ref` is a normal prop** (React 19).
- **Boolean controls.** `Checkbox` and `ToggleSwitch` use `checked/defaultChecked/onChange` with native React input events. `RadioGroup` requires a name, distributes `value/defaultValue` and reports `onValueChange(value, event)`; `RadioButton` supplies a string or number value. JSX children are independently typed, so keep option values in the root union and their serialized strings distinct. Uncontrolled selection/reset are native; changing defaults follows React/HTML semantics. Controlled state and reset remain caller-owned. `readOnly` vetoes activation while preserving focus and submission; native disabled fieldsets work normally. `indeterminate` is applied after checkbox renders, clears on native activation, and does not change submission.
- **State ownership.** State callbacks follow the migration policy. Native inputs support controlled and uncontrolled values. `Select`, `Combobox`, `InputNumber` and `SearchField` require controlled values; their callers own value and form-reset policy. Selection components document their empty values. Open/disclosure state follows Base UI's controlled/uncontrolled API.
- **Variants are props:** `severity`, `size`, `variant`. They render as `data-*` attributes, which you can use in your own CSS.
- **Icons are `ReactNode`s.** Bring your own icon library or inline SVGs. Icons next to text are decorative; give icon-only buttons an `aria-label`.
- **Forms.** Spread the `FormField` render-function props onto one labelable control to connect its label, hint and error. Flat `Field` parts use explicit `htmlFor`, IDs and ARIA attributes. Validation state and error content belong to the caller; native constraints belong on the control.
- **Class names** start with `tumaet-ui-`. They are stable and usable for styling, for example `tumaet-ui-btn`.
