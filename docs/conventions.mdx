# Conventions

Component pages document their supported props. The [API and migration policy](https://github.com/ls1intum/tum-aet-ui-react/blob/main/docs/migration-policy.md) defines state conventions and compatibility requirements.

- **Element props and refs.** `Input` and `Textarea` forward native props and refs directly. `Checkbox`, `RadioButton` and `ToggleSwitch` forward native control props and refs to their inputs. Custom rendering and composite components document their prop targets.
- **`ref` is a normal prop** (React 19).

- **Controlled or uncontrolled.** State callbacks follow the migration policy. `Input` and `Textarea` use native DOM events and text values. Selection components document their empty values; `undefined` leaves state uncontrolled.
- **Variants are props:** `severity`, `size`, `variant`. They render as `data-*` attributes, which you can use in your own CSS.
- **Icons are `ReactNode`s.** Bring your own icon library or inline SVGs. Icons next to text are decorative; give icon-only buttons an `aria-label`.
- **Forms.** Spread the `FormField` render-function props onto one labelable control to connect its label, hint and error. Flat `Field` parts use explicit `htmlFor`, IDs and ARIA attributes. Validation state and error content belong to the caller; native constraints belong on the control.
- **Class names** start with `tumaet-ui-`. They are stable and usable for styling, for example `tumaet-ui-btn`.
